# Domain documentation

AGP has a single context. Read root `GLOSSARY.md` when it exists and relevant decisions under `Docs/adr/` before designing changes. Missing documents need no setup warning: create them when a term is agreed or a decision needs recording.

Use `Docs` with that capitalization, matching the existing repository. Store ADRs as `Docs/adr/<NNNN>-<decision>.md`. Keep the glossary about concepts; put implementation choices in ADRs or feature specs. Existing engine and gameplay guides remain the starting point for understanding current behavior.

Use agreed terms consistently. Surface a conflict with an existing ADR before changing the decision.
